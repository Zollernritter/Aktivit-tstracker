Tag 1: Den bestehenden Daily Recap verstehen
3–4 Stunden
Du weißt genau, welche Teile du ändern musst.
[ ] Den aktuellen Ablauf einmal vollständig durchspielen
[ ] Alle festen Fragen und Antwortmöglichkeiten auflisten
[ ] Festhalten, wo die aktuelle Antwort gespeichert wird
[ ] Den Code gedanklich oder in Dateien trennen: Fragen, Oberfläche, Antwortverarbeitung
[ ] Eine Kopie oder einen Git-Commit des aktuellen Standes sichern


Tag 2: Antwortbuttons dynamisch erzeugen
4–5 Stunden
Die Antwortmöglichkeiten kommen aus einer Liste.
[ ] Für eine einzelne Frage die Antworten als Liste bereitstellen
[ ] Für jeden Eintrag automatisch einen Button erzeugen
[ ] Beim Klick den ausgewählten Wert speichern
[ ] Die ausgewählte Antwort visuell markieren
[ ] Nach der Auswahl zur nächsten Frage wechseln


Tag 3: Zurückgehen und Fragen überspringen
4–5 Stunden
Der Nutzer kann den Frageablauf kontrollieren.
[ ] Einen aktuellen Fragenindex verwalten
[ ] Eine Zurück-Schaltfläche ergänzen
[ ] Beim Zurückgehen die vorherige Antwort wieder anzeigen
[ ] Eine Überspringen-Schaltfläche ergänzen
[ ] Übersprungene Fragen von beantworteten Fragen unterscheiden


Tag 4: Tagesabschluss und Fehlerfälle
4–5 Stunden
Der Daily Recap hat einen klaren Anfang und Abschluss.
[ ] Eine Fortschrittsanzeige wie Frage 3 von 8 einbauen
[ ] Am Ende eine Zusammenfassung der Antworten anzeigen
[ ] Prüfen, ob übersprungene Fragen leer bleiben oder als übersprungen markiert sind
[ ] Den Tagesabschluss eindeutig gestalten
[ ] Festlegen, was beim erneuten Öffnen am selben Tag passieren soll


Tag 5: Antworten und Tagesdaten speichern
4–5 Stunden
Die Datenstruktur ist bereit für die spätere Datenbank.
[ ] Jeder Frage eine stabile ID geben
[ ] Antworten anhand der Frage-ID statt nur anhand ihrer Position speichern
[ ] Das Datum des Recaps festhalten
[ ] Die vorhandene Speicherung testen und Fehler beheben
[ ] Die Speicherung so kapseln, dass sie später durch Supabase ersetzt werden kann


Tag 6: Oberfläche und Bedienung testen
3–5 Stunden
Die Abfrage ist angenehm nutzbar.
[ ] Buttons, Abstände und Beschriftungen verbessern
[ ] Auf Smartphone-Breite testen
[ ] Schnell hintereinander klicken und Sonderfälle prüfen
[ ] Eine bereits ausgewählte Antwort ändern und kontrollieren
[ ] Alle Fragen einmal vollständig und einmal mit Überspringen durchspielen


Tag 7: Puffer und nächste Etappe
2–4 Stunden
Ein stabiler Zwischenstand ist fertig.
[ ] Die wichtigsten offenen Fehler beheben
[ ] Den funktionierenden Stand sichern
[ ] Notieren, welche Daten lokal gespeichert werden
[ ] Die geplante Supabase-Datenstruktur skizzieren
[ ] Login nur anfangen, wenn die Kernfunktionen zuverlässig laufen
